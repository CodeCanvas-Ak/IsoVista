# 05 · History Synthesizer

## 1. 定位

历史模块包含三件不同的事，不应混为一个“大数据中枢”：

1. **归一化与导出**：加载、校验和转换现有 text/Elle 历史。
2. **结构变换**：投影、重命名、裁剪等确定性操作，服务回归和 reducer。
3. **历史合成**：直接构造满足或违反指定规格的历史。

当前主线只需前两项的最小能力。CEGIS、允许值枚举和 mock storage 是后续研究功能，不是平台其他模块的前置条件。

## 2. 近期原则：复用现有模型

现有 `History / Session / Transaction / Operation` 继续作为读写寄存器模型。只有在第二种数据模型真实进入主线时，才抽取更通用的 IR，避免提前建立一个所有字段都可空的“超集”。

需要通用 IR 时，至少显式保存：

| 信息 | 目的 |
| --- | --- |
| `schema_version/model` | 区分读写寄存器、list-append 和未来 SQL 模型 |
| 会话、事务、操作及顺序 | 保留基本历史结构 |
| 观测完整性 | 区分完整黑盒历史与部分观测 |
| checker 假设 | 唯一写值、初始化事务、aborted 语义等 |
| 扩展字段 | 谓词、行集、版本或时间戳，按模型启用 |

加载和导出不得悄悄丢弃扩展字段；不支持的转换应明确报错。

## 3. 归一化流水线

```text
text / Elle / trace
       │
       ▼
Parser ──▶ Structural validation ──▶ History
                                      │
                                      ├─▶ Exporter ──▶ text / Elle / checker input
                                      └─▶ Transform ──▶ projected or normalized history
```

校验至少覆盖：

- ID 唯一、事务与会话归属一致、操作顺序可重建。
- 读值来源和初始化写符合当前模型假设；无法推断时报告原因。
- aborted、重复写值和空读按模型处理，不靠格式猜测。
- 转换前后保留必要的来源和语义标签。

## 4. 结构变换：优先实现

| 变换 | 用途 | 必须保持的不变量 |
| --- | --- | --- |
| `project` | 选择事务或操作子集 | 历史结构合法，依赖来源不悬空 |
| `rekey/revalue` | 规范化键值，辅助去重 | 相等关系与读写匹配不变 |
| `crop-to-cycle` | 聚焦反例及必要支撑事务 | 不丢失解释反例所需上下文 |
| `export` | 对接现有或外部 checker | 模型和假设不发生变化 |

每次变换记录输入哈希、参数和输出哈希，使 reducer 或图表能追踪来源。

## 5. 定向历史合成：按需实现

### A. 异常模板

最先落地的是 2～4 个事务的最小 accept/reject 对例，用于 checker 回归和教学演示。模板来自明确的异常定义，并由现有 checker 双向验证。

### B. 规格区分合成

用有界枚举或 SMT 搜索“规格 A 接受、规格 B 拒绝”的历史，可用于研究规格差异。实现前必须已有机器可读规格和独立 oracle，不能仅用一个 checker 证明自己正确。

### C. 允许值与 mock storage

根据弱隔离规格为应用读操作选择合法返回值，属于应用测试方向，与当前毕设主线分离，暂不展开。

## 6. 验收

- 现有 text/Elle 样例往返加载和导出后，结构及兼容 checker 的判定不变。
- 每种 transform 都有最小正反测试，并能记录输入、参数和输出哈希。
- 合成的每个历史都标注目标规格、预期结论和假设，且被至少一个独立测试确认。
- SQL 或白盒字段未实现时保持缺省，不以空值宣称已经支持对应语义。
