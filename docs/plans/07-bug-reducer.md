# 07 · Bug Reducer

## 1. 定位与边界

Reducer 用于把大型反例缩小为更容易理解和回归的历史。必须先区分两种任务：

- **离线历史归约**：以 checker 为 oracle，删除事务或操作后仍保持目标违例。实现简单、确定性强，适合作为第一步。
- **数据库复现归约**：在真实 DBMS 上重放并仍触发同一问题。受调度与并发控制影响，是后续独立能力。

离线历史变小并不自动意味着获得了可提交给数据库厂商的最小复现脚本，两者不能混写验收。

## 2. 离线历史归约

### 输入

- 原始历史及其哈希。
- checker、隔离规格和完整配置。
- 原始 `reject` 结果与可用的反例信息。
- 需要保持的异常签名；没有签名时至少保持同一 checker、同一规格下的 `reject`。

### 过程

```text
验证原始历史可稳定复现 reject
              │
              ▼
按事务粗粒度归约 ──▶ 按操作细粒度归约 ──▶ 规范化与最终复核
              │              │                    │
              └──── 每次候选都重新加载并验证 ──────┘
```

1. 优先删除整个非关键事务，再尝试删除操作，减少无效组合。
2. 每次删除后先校验历史结构；读值来源、初始化和事务边界不合法时直接丢弃候选。
3. 能利用反例时保留环及支撑事务，减少搜索；不能只保留环而破坏历史语义。
4. 使用确定性预算和固定遍历顺序，记录每次尝试及结果。
5. 最终重新加载输出，独立运行 checker 复核，而不是沿用中间缓存。

## 3. 输出

```text
reduction/<case-id>/
├── original.ref             # 原始历史哈希与位置
├── minimal_history.txt
├── checker.yaml
├── reduction.json           # 尝试次数、耗时、前后规模、异常签名
└── counterexample.dot       # 最终反例，可选
```

归约结果通过 02 的来源和预期结论审核后，才能加入回归集。原始终产物仍保留，便于审计误删。

## 4. 去重：后置增强

先使用确定性指纹做粗筛：数据模型、隔离规格、异常类型、事务规模、规范化操作形状和反例图特征。只有候选指纹接近时才进行图同构或人工复核。

不同数据库版本或不同表面 SQL 不能直接证明是不同 bug；反例环不同也不能直接证明是不同根因。去重结论应带依据和置信状态，不引入多 Agent 框架作为必要依赖。

## 5. 数据库复现归约：可选

只有 04 已支持可控重放、barrier 或延迟注入后再启动。每次重放都要记录数据库版本、隔离级别、调度约束和多次复现结果。无法稳定复现时保留为概率性 case，不包装成确定性复现。

## 6. 验收

- 默认样例归约后仍是合法历史，并在独立复核中保持指定 checker 与异常签名。
- 同一输入和配置得到相同的最小历史及归约日志。
- 输出包含前后事务数、操作数、验证次数和耗时，但不预设必须达到某个缩减比例。
- 至少保留一个无法继续归约的反例作为回归，防止未来修改破坏归约语义。
- 数据库复现能力未验证时，文档和 UI 只称为“历史归约”，不称为“数据库最小复现”。
