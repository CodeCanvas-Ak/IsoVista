# 11 · 单人实施路线图

## 1. 编排原则

本路线按**一个人顺序实现**设计，不设置团队分工或固定周期。优先级由依赖关系和毕设价值决定：先可信基线，再回归与实验，随后展示和论文；高级模块不得挤占主线。

```text
阶段 0 基线 → 阶段 1 回归与记录 → 阶段 2 实验与图表 → 阶段 3 演示 → 阶段 4 论文交付
```

每个阶段结束都应留下可运行版本。进入下一阶段前，把实际契约和验证结果回写到 ROADMAP 或对应专题文档。

## 2. 阶段 0：恢复可信工程基线

### 任务

1. 使用 JDK 11 跑通 Java 编译、局部测试和全量测试，记录真实失败；不要用升级业务代码掩盖 JDK 25/Lombok 环境问题。
2. 为 `history.path` 被整体转小写、历史类型使用 `==` 分别建立最小回归，再做局部修复。
3. 用 TCC 样例核实 `ELLE_TRANSACTIONAL_CAUSAL_CONSISTENCY` 当前映射到 `SNAPSHOT_ISOLATION` 的影响，确认语义后再修。
4. 保持示例配置无个人路径和真实口令，完成一次文本历史 CLI 冒烟；随后验证一次 FastAPI 队列运行。

### 验收

- JDK 11 下的构建与测试结果有记录，文本历史 CLI 可从干净目录重复执行。
- 上述三个问题均有明确结论和回归；未验证的外部 checker、数据库与 Docker 明确标为未验证。
- 前端构建、后端语法检查和本地启动步骤与文档一致。

对应入口：根目录 `ROADMAP.md` 的当前风险。

## 3. 阶段 1：回归历史与统一运行记录

### 任务

1. 按 02 核验现有 SI、SER、TCC 样例，建立最小 regression manifest，并补 accept/reject 对例。
2. 按 06 在现有 checker 外层统一 `accept/reject/timeout/oom/error/skipped`，先不改算法内部。
3. 按 10 定义最小 `run.json` 和实验目录，保存配置、代码版本、历史哈希、日志和产物引用。
4. 为 loader、serializer、checker 结果解析和后端关键 API 补回归或冒烟。

### 验收

- 同一回归集可重复运行并输出逐用例结果，异常状态不会被写成 accept/reject。
- 任一结果都能追踪到输入、配置和代码版本；不兼容 checker 会被跳过并说明原因。
- 当前三个原始样例的来源与预期结论经过实际验证，而不是只迁移文件名。

对应文档：02、06、10。

## 4. 阶段 2：实验矩阵与论文图表

### 任务

1. 实现最小 YAML 展开器，复用现有 CLI，先支持单维扫描和多 checker，再增加少量多维组合。
2. 保存原始 profile 与 09 的环境、预算、实际规模和资源指标。
3. 实现独立分析脚本，生成 verdict 表、耗时/内存曲线和阶段图。
4. 选定一组核心对照实验，按统一历史、预算和环境重复测量。

### 验收

- 论文候选表格和图只由 artifact 一键重建，数字可回链到原始 run。
- 中断续跑、重复实验和失败状态处理经过实际测试。
- 报告包含实验协议、缺失数据和局限，不使用无法复现的绝对性能结论。

对应文档：09、10；负载复现所需的最小改动见 03。

## 5. 阶段 3：演示与异常解释

### 任务

1. 按 08 固定图 DTO，保留原始 DOT 下载，并补解析失败和缺字段测试。
2. 优化反例环聚焦、边图例、事务详情和推导展开，复用 `dgraph_si` 作为默认演示。
3. 打通上传历史或配置运行、查看结果、下载 artifact 的 Web 闭环。
4. 整理本地启动、测试库准备和演示数据，不依赖公共服务器或口头补充路径。

### 验收

- 新环境按 README 可启动演示，核心页面数据与 artifact 一致。
- 演示至少覆盖一个 accept、一个 reject 和一个运行失败场景。
- 大图和非法输入有明确降级或错误提示。

对应文档：08 及根目录使用文档。

## 6. 阶段 4：论文与答辩交付

### 任务

- 使用阶段 2 的原始结果撰写实验章节，保留系统架构、核心流程、对照实验、失效案例和局限。
- 冻结一组演示数据、配置和依赖版本，完成一次干净环境复现。
- 检查文档、脚本、图表和论文中的名称、口径与数字一致。

### 验收

另一位使用者只依据仓库文档即可构建、运行核心回归、重建图表并完成演示，不需要个人机器路径或隐式手工步骤。

## 7. 主线后的扩展选择

主线完成后，根据论文证据最多选择一个方向做深，不同时铺开：

| 方向 | 启动条件 | 文档 |
| --- | --- | --- |
| 模板或 Mini-Transaction 生成 | 能证明相对现有随机负载的覆盖或效率收益 | 03 |
| SQL 谓词垂直链路 | 同时实现最小 trace、历史语义、兼容 checker 和 phantom 用例 | 04、05、06 |
| 离线历史 reducer | 已有足够大的真实反例和稳定 checker oracle | 07 |
| 新数据库或 checker | 能形成新的语义或性能对照，而非增加列表长度 | 04、06 |
| 高级合成、在线检查、白盒加速 | 作为后续研究，不纳入当前必做交付 | 05、06 |

## 8. 风险控制

| 风险 | 控制方式 |
| --- | --- |
| 范围蔓延 | 以阶段验收为唯一推进条件，可选模块不阻塞主线 |
| 环境长期不可用 | 先固定 JDK 11 和 Linux/容器基线，外部依赖分开标注 |
| 重构引入正确性回归 | 先建历史与结果回归，再用适配器逐步迁移 |
| 实验结论不可信 | 同历史、同预算、同环境，保留失败和原始数据 |
| 文档再次膨胀 | 当前事实只写 ROADMAP，目标契约写专题，执行顺序只写本文 |

## 9. 当前唯一入口

从**阶段 0**开始。完成前不并行启动 SQL IR、完整插件框架、reducer、历史合成或大规模数据库扩展。
